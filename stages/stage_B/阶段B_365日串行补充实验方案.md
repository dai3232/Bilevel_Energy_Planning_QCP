# Stage B-2C：365 日串行递推 IPM 补充实验方案

## 身份与阶段边界

- 实验身份：`B-2C-365-SERIAL-RESUMABLE`。
- 日期范围：第 1—365 日；每日 24 小时。
- 本实验是 Stage B-2C 的独立规模扩展证据，不改变已收口的 Stage B `PASS`，不属于 Stage D1，不执行并行。
- 当前 `stage_D1 / READY` 与 `DECISION-D1-01` 保持不变。

## 模型与算法口径

- 每日 SOC 独立闭合：日初、日末均为 `0.5E`，日期之间无 SOC 连接。
- 火电只使用第一次连续口径 `0 <= Pf <= Pmax`；不执行 C1/C2、火电掩码和第二次求解。
- 使用 365 个日内联合块按日串行求解和 16 维全局核心；不启动并行池。
- 递推 Newton 方向是唯一正式方向；不装配、不求解完整 KKT，也不存在完整方向回退。
- 保留全不等式消元、每日水量约束和精确水量松弛二阶校正。
- 从现有初始化器构造统一内点初值，不使用 30 日结果或前一日结果热启动。

## 收敛与验证

- 最大接受迭代数为 100。
- 等式原始残差、不等式原始残差、统一尺度对偶残差和统一尺度平均互补间隙阈值均为 `1e-6`。
- 每轮递推方向以重构 KKT 相对残差 `<=1e-8` 为方向门禁；日块和
  16 维核心的局部 LDL 求解目标保持 `<=1e-10`。
- 收敛后执行最终物理审计；正式验证只使用递推方向重构 KKT 残差、四项收敛指标和最终物理审计。

## 检查点与断点续算

- 初始状态保存为第 0 号检查点；每次接受迭代完成后保存一个不可覆盖检查点。
- 恢复时必须显式传入原运行目录 `runs/<run_id>`；不得自动搜索其他运行。
- 恢复仍使用原 run_id，校验有效配置、受控输入、求解代码身份、检查点哈希链、状态指纹和重建线性化指纹后，从最新已接受迭代的下一轮继续。
- 若在某轮第若干日处理中断，该轮尚未接受，恢复后从该轮第 1 日重新计算；此前已接受迭代不重算。
- 检查点和逐轮证据读写时间单独记录，不计入纯递推 IPM 数值计算时间；端到端墙钟时间如实包含这些开销。

## 最终工件

- 同一运行目录持续追加检查点、迭代历史、因子记录、水量二阶校正记录和恢复事件记录。
- 收敛后输出容量结果、逐小时调度、各类电源每日发电量、最终物理审计和中文 Word 报告。
- 运行终态只按 `PASS`、`FAIL_RETRYABLE`、`BLOCKED_EXTERNAL` 或 `NEEDS_MODEL_DECISION` 记录。

## 调用方式

- 新运行：`rkkt.workflows.stageB2C365DaySerialExperiment()`。
- 原运行恢复：`rkkt.workflows.stageB2C365DaySerialExperiment(ResumeRunDirectory="<项目根>/runs/<run_id>")`。
- 恢复调用不得同时传入 `RunId`；恢复目标必须是原运行的完整目录，而不是只给 run_id，程序也不会搜索其他运行目录。

## 当前实施状态（2026-08-12）

- 配置、串行求解入口、同一 run_id 恢复、检查点链、索引复用、恢复事件、累计计时和中文报告生成均已实现。
- 断点续算定向单元测试 `9/9 PASS`；增强后的检查点加载器已兼容读取既有权威七日运行的 0—30 号检查点链。
- 365 日真实数据的正式 IPM 运行尚未启动；当前文件记录的是已就绪的执行方案和代码状态，不包含 365 日数值结果。
