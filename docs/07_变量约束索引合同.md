# 变量、约束与索引合同

## 规范变量顺序

1. 全局容量 `q`，严格 14 维：风 5、光 5、储能功率 2、储能能量 2。
2. 按日期顺序放置日容量副本 `q_d`。
3. 按日期、小时顺序放置活动小时变量：活动风电、活动光伏、水电 4、火电 4、Pch 2、Pdis 2、SOC 2。

## 规范等式乘子顺序

1. 两条全局储能时长乘子 `rho`。
2. 每日容量绑定乘子 `pi_d`。
3. 每小时功率平衡、SOC1 递推、SOC2 递推乘子。
4. 最后小时追加两条末端 SOC 等式乘子。

## 规范不等式顺序

1. 全局容量 28 条上下界。
2. 按日期、小时、小时变量顺序排列局部下界、上界。
3. 固定零变量不创建原变量、两条界、松弛或乘子。

## 方向顺序

完整方向统一为 `d=[Delta_xi; Delta_y; Delta_l; Delta_z]`。递推求解可使用显式置换，但必须保存 `permutation_map.csv` 并逆置换回规范顺序后再比较。

Stage A3 的 `permutation_map.csv` 专指 4340 维约化鞍点系统从规范约化顺序到递推求解器顺序的真实排列，不得用完整方向的恒等映射代替。该表必须逐行记录递推索引、规范约化索引、正向与逆向映射、变量或等式空间、局部规范索引以及所属日、小时、日链或年度核心对象；两侧索引都必须是 `1:4340` 的唯一双射，排列必须非恒等，正逆复合必须严格恢复恒等映射。完整 11588 维规范方向的语义恒等表如需保留，使用 `canonical_index_map.csv`，不得称为递推排列。

## 固定零映射

每个被删除变量必须记录日期、小时、设备类型、设备编号、删除原因、物理数组位置和 `notApplicable` 的不等式方向状态。不得用极小正上界代替精确删除。

## 索引证据

每次运行必须生成：`variable_index.csv`、`constraint_index.csv`、`block_index.csv`、`fixed_zero_map.csv`、`permutation_map.csv`。Stage A3 还必须生成 `canonical_index_map.csv`，并在递推 MAT 证据中保存 `partition.permutation`、正向与逆向排列、`partition.assembly_audit` 以及日链、年度核心与规范系统的装配关系。索引必须无重叠、无缺口，并可从活动向量可逆恢复物理数组。
