# PKG-00 包接口重构路线与边界 v1.0

## 1. 定位

`PKG-*` 是独立的工程重构辅助轨道，不是数学模型阶段，也不替代
`CURRENT_STAGE.md`。正式项目继续保持 `stage_A4 / READY`，只有正式
Stage A4 的阻断验收才能决定是否进入 Stage B。

重构目标是建立：

- `rkkt.*` 包命名空间；
- 稳定、窄小的公共函数接口；
- 明确的结构体输入输出合同；
- 每个模块可人工单独运行的验证入口；
- 生产算法、阶段编排、诊断、证据和报告之间的清晰边界。

## 2. 冻结边界

包接口重构不得：

1. 修改数学模型、目标、约束、变量顺序或索引语义；
2. 修改第14—20日七日范围或每日 SOC 首末 `0.5E` 口径；
3. 改变完整 KKT 仅作为审计路线、递推方向作为正式路线的定位；
4. 改变 `sigma`、`tau`、步长、最大迭代次数或收敛阈值；
5. 增加正则化、伪逆、显式逆、自动对称化或完整方向回退；
6. 移动、覆盖、删除或重新打包历史 `runs/`；
7. 把用户人工模块检查替代为正式阶段验收；
8. 把正式阶段验收逻辑写进人工验证运行文件。

## 3. 两类验证必须并存

### 3.1 人工模块验证

每个模块具有独立运行入口，固定读取上一级用户已确认的 `.mat`，保存：

- 当前模块实际输入；
- 正式生产输出；
- 数学中间量；
- 客观诊断指标；
- 中文 CSV 表；
- 中文 `.fig` 与 `.png`。

人工验证文件不得写 `PASS/FAIL`，不得自动运行下一级。

### 3.2 自动回归与正式验收

现有单元测试、集成测试、方向等价门限、Stage 验收矩阵和唯一
`runs/<run_id>` 证据继续保留。它们与人工模块验证互补，不能互相替代。

人工验证固定输出允许覆盖；正式 `runs/<run_id>` 永不覆盖。

## 5. 九个辅助阶段

| 阶段 | 范围 | 停止条件 |
|---|---|---|
| PKG-0 | 基线、模块映射、接口合同、依赖规则 | 用户确认设计 |
| PKG-1 | `+rkkt` 空包骨架和公共基础设施 | 无生产算法迁移 |
| PKG-2 | 数据接口与数据人工验证 | 新旧数据输出一致 |
| PKG-3 | 索引接口与索引人工验证 | 规范索引和固定零映射一致 |
| PKG-4 | 状态与统一线性化接口 | 残差/Jacobian/Hessian 同源 |
| PKG-5 | 完整 KKT 与既约 KKT 接口 | 同一线性化、同一方向基准 |
| PKG-6 | 小时链、日响应、16维核心、回代和等价性 | 递推方向门限保持 |
| PKG-7 | IPM 单步、完整迭代和工作流 | 状态轨迹与旧入口一致 |
| PKG-8 | 调用迁移、旧入口退役和文档收口 | 全部相关回归通过 |

每个阶段只允许一个清晰提交；若阶段未达到其冻结门槛，不得把失败实现
接入下一阶段。

## 6. 包接口迁移策略

采用“薄门面—逐步迁移”：

1. 先创建 `rkkt.*` 公共函数；
2. 公共函数只调用现有正式生产函数；
3. 合同函数只核查，不修改输入；
4. 新旧入口在同一输入上对照；
5. 新代码逐步改为调用包接口；
6. 旧入口先成为兼容包装；
7. 只有调用者清零且回归完成后，才允许删除重复旧入口。

不得在包内复制一套生产算法。
